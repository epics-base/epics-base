### New `set` and `show` commands for iocsh variables

Since EPICS 3.15.1 the IOC shell command `iocshLoad` has been provided to run
an iocsh script and pass it `variable=value` settings for iocsh variables that
are limited in scope to that script.
However there was no way to set variables inside a script that would also
disappear when it ends.

This release includes a new iocsh command `set` which has 4 different behaviors:

+ `set name value` sets the iocsh variable in the current scope
+ `set -name` marks `name` as deleted in the current scope without affecting
  the parent scope
+ `set pattern` displays the value of all matching variables in this scope
+ `set` displays all iocsh variables in the current scope

Scripts that set variables which must be visible after the script ends should
continue to use `epicsEnvSet` or `epicsEnvUnset`.
These both delete any iocsh variables with that name in all iocsh scopes.

Any iocsh variables given the same name as an environment variable will hide the
environment variable when iocsh expands `${name}` or `$(name)` in the current
and any child scopes.
The original value will reappear when the iocsh variable goes out of scope.

A new macLib routine was added to libCom to support the ability to display the
macros stored in a handle.
`long macIterateMacros(handle, callback, user)` calls `callback()` for each
macro defined in `handle`, passing it `user` followed by the macro's name and
fully-expanded value as strings. See macLib.h for details.
