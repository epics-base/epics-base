### Lock-free callback queues with per-worker wakeups

GitHub [PR #996](https://github.com/epics-base/epics-base/pull/996)

The callback queue of each priority is now lock-free:
a request pushes onto an inbox with one atomic operation and never blocks,
a callback that blocks holds back no other queued callback,
which runs on any free worker thread,
and a worker that stops making progress is replaced by a sleeping one.

Two limits are new.
`callbackParallelThreads()` runs at most 64 threads per priority
(32 on 32-bit targets); a larger count is reduced to that
with a message at `callbackInit()`.
On 32-bit targets `callbackSetQueueSize()` rejects sizes of 65535 or more.

`callbackQueueStatus()` and `callbackQueueShow` count entries in use:
a worker returns the entries it has run in batches of 16
or when it goes idle, so `numUsed` can exceed the number waiting
by up to 16 per thread, and the queue is full when `size` entries are in use.

On Linux `epicsEvent` is now built on a futex
instead of a mutex and condition variable,
so triggering an event never takes a lock a preempted thread may hold.
