### Remove special meaning of `grecord`

In 1996, the db file keyword `grecord` had been added in addition to `record`
to mean a record "visible for graphic editors" (commit 09ce706).
That commit has now largely been reverted.

The concept of "visible" versus "invisible" records was undocumented and
never meant anything within EPICS base. Editors for db files should be able
to "see" all records in the file.

The functions `dbVisibleRecord()` and `dbInvisibleRecord()` have been removed.
The function `dbIsVisibleRecord()` has been kept in case any external code
uses it but it is now an inline dummy function that always returns 1 and has
been marked deprecated.

The keyword `grecord` has been kept in order not to break existing db files
but it has become an alias for `record`. Functions that print records, for
example `dbDumpRecord`, now always print `record`.
